# Architecture (foundation)

- `frontend/`: React + TypeScript + Vite; React Router owns client navigation. Three.js and React Three Fiber render the procedural world and upper-terrace bazaar; Drei is installed but not needed for this slice. `world/` owns geometry, terrain/collision, typed decorative stall configuration and the follow camera; `components/` owns touch controls and the native dialog; `App.tsx` owns input, entry and HUD. CSS provides lightweight styling. Frontend code must not own payment verification, pricing authority, or database credentials. See [`PLAYABLE-WORLD.md`](PLAYABLE-WORLD.md) and [`BAZAAR.md`](BAZAAR.md).
- `backend/`: independently runnable Node.js + Express + TypeScript service. `src/server.ts` validates environment and starts the process; `src/app.ts` defines HTTP behavior for testing without opening a port. Zod validates inputs at the HTTP boundary. No database connection yet.
- `docs/`: decisions and planned contracts. No root workspace manager; each app has its own manifest and lockfile.

Planned integration: browser calls a versioned API on a separately hosted backend using a configured base URL. Before cross-origin integration, add an explicit origin allowlist; before private endpoints, implement authentication and backend authorization. The backend alone will access Supabase PostgreSQL using server-side credentials and enforce booking and payment invariants in database transactions. If Supabase Auth is adopted, verify tokens server-side and check roles in the database; do not trust client-supplied roles. Use database constraints and row-level security appropriate to the chosen connection mode. Never ship service-role keys in Vite environment variables.

Proposed hosting: frontend on Vercel, backend on a separate Node.js host, database on Supabase. None is provisioned. Three.js scenes should later be loaded on demand, use asset budgets and mobile quality tiers, and retain usable non-3D navigation. Original assets only.
