## Explicit local/demo testing

From `backend/`, after `npm ci`, run e.g. `DEMO_MODE=true ADMIN_API_TOKEN="$(openssl rand -hex 32)" npm run dev` (macOS/Linux). Start `frontend` with `npm ci && npm run dev`. The generated token is needed only if testing the Organiser view; save it privately for that local session. With no Supabase and without `DEMO_MODE=true`, writes return HTTP 503 rather than pretending to persist. Demo records and settings vanish when the backend process restarts. Demo never displays payment QR or live UPI instructions. No user secrets are required to explore the world.

## Limits

The contribution workflow records references for **human review**, not verified transactions. The demo store is per-process memory and unsuitable for real payments. Rate limiting is per Express instance and should be complemented by reverse-proxy protection in a multi-instance deployment. There are two physical vendor kiosk slots; all further approved/published vendors appear in the in-world directory rather than occupying simulated stalls. Expiry is evaluated when listings are read; rental duration begins at approval. Real privacy/compliance procedures, transaction reconciliation, backups and load/security review remain organiser responsibilities.
